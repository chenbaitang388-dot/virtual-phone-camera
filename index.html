◉ 虚拟手机摄像头
WebGL WebRTC 无构建步骤
它是怎么实现的
电脑上的页面会画出一个 360° 全景的 3D 场景，场景里浮着一台 3D 手机模型。 你在手机浏览器里打开同一个站点，手机把陀螺仪读到的姿态实时发到电脑， 电脑就用它来旋转场景里那台虚拟手机 —— 于是真手机转多少度，虚拟手机的摄像头就转多少度。 电脑端还能用 WASD 带着虚拟手机在场景里走动，像一个真人一样边转视角边走路。 按下录制后，录的是虚拟手机摄像头第一人称看到的那块画面。
  1. 在电脑上打开电脑端页面，它会给出一个 6 位房间码和一个二维码。
  2. 用手机相机扫那个二维码（或手输房间号），手机端页面就打开了。
  3. 手机上点一下「启用陀螺仪」，然后拿着手机转动，电脑里的虚拟手机就会跟着转。
  4. 点电脑端的「开始录制」，录出来的是虚拟手机的第一人称视角。
手机上不需要装任何 App，电脑上也不需要装 Blender 之类的软件，全部在浏览器里跑。 但注意：手机浏览器只在 HTTPS 页面里才允许读取陀螺仪，所以请用部署好的网址访问，不要用局域网 IP。
先选一个角色
🖥 我是电脑 显示 3D 场景和那台虚拟手机，出房间号和二维码，负责录制视频。 📱 我是手机 打开陀螺仪，用真手机的姿态遥控电脑里那台虚拟手机的摄像头。

正在判断这是电脑还是手机…

两边都要开着这个页面，电脑端和手机端是同一个站点的两个页面，通过房间号配对。 手机端也可以只用手指在屏幕上拖动来转视角（不用陀螺仪也能玩）。
依赖与实现细节
3D 渲染 three.js（已内嵌在 vendor/，不走外部 CDN）
配对通道 WebRTC 点对点 + MQTT 中转，两条同时发，谁先到用谁
录制 MediaRecorder 抓 canvas，导出 .webm
这个仓库是纯静态站，没有任何构建步骤 —— 推到 GitHub 之后由 GitHub Pages 直接发布， 顺带拿到 HTTPS（手机陀螺仪必需）。想了解完整架构和常见问题，看仓库根目录的 README.md。
